## Slide 2 — Overview
- A fraud-detection pipeline + analyst dashboard that scores every payment
  transaction and explains every score.
- Built end-to-end in pure Python standard library with a zero-dependency
  static dashboard.
- Validated honestly against the rules-only baseline it is designed to
  replace — on a held-out test set, with every figure reproducible from the
  included artifacts.

## Slide 3 — Problem
- Fraud is ~2% of payment traffic but drives outsized losses and review cost.
- Legacy rule systems miss evolving patterns (on our test set, rules miss
  20 of 52 frauds).
- Black-box scores can't answer "why was this blocked?" — for customers,
  auditors, or regulators.
- Analysts need three things: catch more fraud, keep false alerts low, and
  explain every flag.

## Slide 4 — Solution
- **FraudLens**: logistic-regression risk scoring over 10 human-readable
  behavioural features (velocity, device, country, night activity, merchant
  risk, account age, amount, distance, recency).
- Coefficients become **reason codes** on every alert — the model is the
  explanation.
- Dashboard with a live threshold explorer: judges can re-tune the
  precision/recall trade-off themselves, recomputed from real test scores.

## Slide 5 — Methodology
- Synthetic dataset of 8,000 transactions (2.14% fraud), generated by a
  seeded script (seed 42) from a stolen-card behavioural process — no real
  customer data, fully reproducible.
- Stratified 70/30 train/test split. Threshold (0.97) selected on training
  data only, frozen before test evaluation.
- Transparent rules baseline (points system) scored on identical test rows.
- Metrics: precision, recall, F1, ROC-AUC, confusion matrix, fraud value
  caught. Per-row predictions published for independent recomputation.

## Slide 6 — Tech Stack
- Python 3 standard library only — data generation, gradient-descent
  logistic regression, Mann-Whitney ROC-AUC. No pip installs, no cloud,
  no paid APIs.
- Static HTML/CSS/vanilla JavaScript dashboard (hand-rolled charts).
- Artifacts: transactions.csv · test_predictions.csv · results.json.

## Slide 7 — Implementation / Demo
- One command: `python3 run.py` → dataset, trained model, results,
  dashboard data.
- Dashboard: metric cards → model-vs-rules table → threshold slider →
  feature-driver chart → flagged-transaction queue with reason data.
- Live demo link accompanies this deck; walkthrough script in DEMO.md.

## Slide 8 — Results & Validation (held-out test, n = 2,401)
| Metric | FraudLens | Rules baseline |
|---|---|---|
| Precision | **93.6%** | 91.4% |
| Recall | **84.6%** (44/52) | 61.5% (32/52) |
| F1 | **0.889** | 0.736 |
| ROC-AUC | **0.997** | 0.981 |
| False alerts | 3 | 3 |
| Missed frauds | **8** | 20 |
| Fraud value caught | **$14,663 / $16,524 (88.7%)** | $13,282 (80.4%) |

- 12 more frauds caught at the *same* false-alert count.

## Slide 9 — What drives the score (interpretability)
- ↑ risk: short gap since previous transaction (fraud bursts), high 24h
  velocity (OR 2.26×/SD), unrecognised device (1.91×), night activity
  (1.87×), 1h velocity, foreign country, distance, merchant risk, amount.
- ↓ risk: older account age (0.60×/SD), longer gap since previous
  transaction (0.13×/SD).
- Every alert in the dashboard carries these drivers as its explanation.

## Slide 10 — Impact
- For a payments team: +23 points of recall at zero extra false alerts
  means more fraud stopped with the same review headcount.
- Explanations cut dispute/audit friction — every block has a reason a
  human can say out loud.
- Zero-infrastructure design (stdlib Python + static page) makes it
  deployable by small processors and fintechs that can't run an ML platform.
- Responsible by construction: synthetic data, no demographic features,
  bias-review flags documented.

## Slide 11 — Limitations & Next Steps (honest)
- Synthetic data → metrics validate the method, not production performance.
- Next: recalibration (scores are rankings, not probabilities), training on
  real labelled data, drift monitoring, cost-sensitive thresholding,
  fairness audit of country/distance features.
