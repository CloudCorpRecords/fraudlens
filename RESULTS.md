# FraudLens — Results (all figures are real outputs of `python3 run.py`)

> Integrity note: every number below was computed by `src/model.py` during the
> run recorded here and is stored verbatim in `results.json`. Per-row test
> predictions are in `data/test_predictions.csv` so anyone can recompute
> every metric independently. Nothing is estimated, rounded into existence,
> or copied from another source.

## Dataset

| Item | Value |
|---|---|
| Source | 100% synthetic, generated by `src/generate_data.py` |
| Reproducibility | Seeded RNG, seed **42** — same command, same dataset |
| Size | **8,000** transactions |
| Fraudulent | **171** (2.14%) — a realistic payment-fraud base rate |
| Features per transaction | amount, hour of day, merchant category + risk, country mismatch, device known, velocity (1h / 24h), account age, distance from home, days since previous transaction |
| Generation model | Fraud drawn from a separate behavioural process (stolen-card patterns: foreign country, unknown device, burst velocity, night hours, high-risk merchants, bimodal probe/cash-out amounts). The detector never sees these rules. |
| Split | Stratified 70/30 (split seed 7): train **5,599**, test **2,401** (52 fraud / 2,349 legitimate) |

## Model

- **Type:** Logistic regression, implemented from scratch in the Python
  standard library (full-batch gradient descent, 900 iterations, lr 0.15,
  L2 = 0.01, positive-class weighting for the 2.14% base rate).
- **Features:** 10 interpretable features (see README). Continuous features
  standardised with training-split statistics only.
- **Threshold:** **0.97**, selected on the *training* split only (maximum F1),
  frozen before any test evaluation. The threshold is high because class
  weighting inflates raw scores — treat scores as risk rankings, not
  calibrated probabilities (a calibration step is future work).

## Rules baseline definition (for fair comparison)

Points: amount > $500 → +2 · country mismatch → +2 · unknown device → +2 ·
velocity 1h ≥ 3 → +2 · night → +1 · merchant risk ≥ 0.7 → +1. Flag at ≥ 5
points. Evaluated on the identical test rows.

## Honest limitations

1. **Synthetic data.** Patterns are learnable by construction, so absolute
   metrics (e.g. AUC 0.997) demonstrate the *method and the interpretability
   layer*, not expected production performance. Real deployment requires
   retraining and recalibration on real labelled transactions.
2. **No calibration.** Class weighting inflates scores; Platt/isotonic
   calibration is the first production upgrade.
3. **Static snapshot.** No concept-drift handling, no adversarial adaptation,
   no cost-sensitive threshold optimisation beyond F1.
4. **Fairness.** No demographic features are used; country/distance features
   would need bias review before any real deployment (travellers and migrants
   are plausibly over-flagged by such features).
